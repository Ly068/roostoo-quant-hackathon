# Team48-Y · 低波动异象 + 风险平价交易系统

**APAC Quant Trading Hackathon 2026 · The University of Hong Kong**

一个完全自主、7×24 运行的加密货币量化交易系统，在 25 个高流动性加密货币上
利用**低波动异象（Low-Volatility Anomaly）**：通过 Parkinson 极差波动率筛选
稳健币种、按波动率倒数加权（Risk Parity），在各种市场状态下追求稳定正收益。

---

## 一、核心策略：低波动异象 + 风险平价

**学术依据：** 低波动异象 / Betting Against Beta（Frazzini–Pedersen 2014）——
经风险调整后，低波动资产往往优于高波动资产；高波动山寨币的"暴涨"常以更大回撤收场。

**每个再平衡时点（72h）的流程：**

```
1. 计算每币 Parkinson 极差波动率（过去168h / 7天）
   - 用 high/low 极差，比收盘价标准差信息效率更高
   - ffill 补缺失；H/L 与 open/close 对齐（防 H=L 死水、插针错乱）
   - Winsorization：单小时极差 clip 到 15% 内（防单根插针污染方差）
2. 趋势过滤：仅当 收盘价 > 168h 均线 才允许做多（不接单边下跌币）
3. 选波动率最低的 50% 币种
4. 按波动率倒数加权（Risk Parity）：低波币权重大、高波币权重小
5. 无符合条件币种 → 空仓避险
```

**为什么是低波、而不是简单动量或做空：**
- 只做多时序动量在震荡市会空仓/小亏；低波策略在震荡市选稳健币，**实测仍正收益**
- 多空横截面动量在 6–10 月上涨轮动市实测亏损（-18%，空头被挤压），故放弃做空
- 倒数加权让账户风险分布均衡，净值曲线不随高波山寨剧烈颠簸

### 动态仓位（比赛阶段自适应）

| 阶段 | 天数 | 仓位系数 | 目的 |
|------|------|---------|------|
| 观察期 | 1-3 | 60% | 开局谨慎，验证信号 |
| 确认期 | 4-10 | 100% | 主力收益期 |
| 收尾期 | 11-14 | 70% | 锁定利润，降低末期风险 |

## 二、风控体系（独立 RiskManager 模块）

| 层级 | 规则 | 动作 |
|------|------|------|
| 单标的灾难止损 | 相对开仓价反向偏离 **12%** | 立即单独平仓，不死等72h |
| 日回撤熔断 | 日内回撤 >4% / >8% | 减仓预警 / 全部平仓暂停1h |
| 连亏熔断 | 连续亏损 3 笔 | 暂停 30 分钟 |
| 敞口约束 | 总敞口 ≤100%（1x，无杠杆） | 硬约束 |

**为什么止损设 12%（而非 3σ 动态）：** 真实回测显示，3σ Parkinson 阈值对低波币
过紧（≈5%~6%），在正常插针处被反复"割肉踏空"，反而降低收益（10次止损、Sharpe 5.3）；
12% 宽止损仅在真正的持续下跌时触发（全周期1次），不损害正常收益、又保留尾部保险。

## 三、回测与稳健性验证

数据：**Binance 公共 1h K线**（volume 完整、价格真实），手续费 **0.1%/边**，72h 调仓。

### 三段独立窗口（互不重叠，每段约29天）

| 窗口 | 市场状态 | 收益 | Sharpe |
|------|---------|------|--------|
| 段1（7月） | 震荡下跌（25币均-5.5%） | **+10.9%** | +1.8 |
| 段2（8月） | 普涨（均+22.8%） | **+11.7%** | +2.3 |
| 段3（9月） | 山寨季（均+36.2%） | **+35.7%** | +4.6 |

全周期（120天）：**+52.1%，Sharpe 6.3，最大回撤 -13.6%，三段全部正收益**。

**关键优势：** 低波异象是对比中**唯一三段全正**的策略——震荡市也赚钱（+10.9%），
不依赖"比赛恰好有强趋势"，市场状态适应性最强。

**诚实说明：**
- 历史 Sharpe 是特定行情的产物，**不能外推、不能承诺**
- 强单边牛市中，低波策略的进攻性弱于纯动量（全周期 52% vs 65%），这是为稳健付出的代价
- 已通过多轮数据审计（含识别并弃用 volume 缺失 / 价格错误的 yfinance 数据）

### 防未来数据泄漏

- 回测引擎逐根 K 线推进，策略只能看到 t 及之前数据（`iloc[:i+1]` 截断）
- 信号、再平衡、止损均严格按时间顺序；冷启动数据截止于比赛开始前

## 四、数据架构（信号源与执行场所分离）

Roostoo 仅提供实时 ticker、无历史 K 线，168h 窗口需预加载：

- **冷启动**：部署时携带 Binance 预下载的 120 天数据（`data/history_binance`）
- **运行时**：每小时用 Binance 公共K线增量追加（volume 完整、与Roostoo价格一致）
- **执行前**：用 Roostoo 实时行情过滤，只在当前有报价币种中选币
- **执行**：Roostoo 负责下单、持仓核对与风控
